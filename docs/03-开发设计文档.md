## 一、技术选型

### 1.1 核心技术栈

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|----------|
| 框架 | Astro | 4.x | 静态站点性能好、SEO 友好、Markdown 原生支持、零 JS 默认输出 |
| 语言 | TypeScript | strict 模式 | 类型安全、开发体验好、可维护性高 |
| 样式 | Tailwind CSS | 3.x | 原子化 CSS、开发效率高、主题系统完善 |
| 国际化 | Astro i18n | 官方 | 路由级国际化、与 Astro 深度集成、零额外依赖 |
| 包管理 | pnpm | 8.x | 速度快、磁盘占用少、lockfile 严格 |
| 部署 | Docker + Nginx | - | 一致性部署、环境隔离、易于扩展 |

### 1.2 为什么选 Astro 而不是 React/Vue

| 对比项 | Astro | React (Next.js) | Vue (Nuxt) |
|--------|-------|-----------------|------------|
| 默认输出 | 纯静态 HTML | SSR/SSG | SSR/SSG |
| JS 体积 | 极小（按需） | 较大（runtime） | 较大（runtime） |
| SEO | 优秀 | 优秀 | 优秀 |
| Markdown | 原生支持 | 需要插件 | 需要插件 |
| 学习成本 | 低（类 HTML） | 中 | 中 |
| 部署复杂度 | 低（纯静态） | 中 | 中 |

**结论**：v0.1 是纯静态展示站，Astro 是最优选择。性能最好、部署最简单、SEO 最友好。

### 1.3 不引入前端框架的原因

v0.1 阶段所有交互（主题切换、语言切换）都可以用原生 JS + Astro 岛屿组件实现，不需要 React/Vue 等框架的运行时。引入框架会：
- 增加 JS bundle 体积
- 增加构建时间
- 增加维护复杂度
- 违背「最小化运行」原则

```typescript
colors: {
```

**Track 2：CSS 变量**（用于动态主题切换）

```css
/* Light 模式 */
:root, [data-theme="light"] {
  --bg-primary: #FFFFFF;
  --bg-secondary: #F8FAFC;
  --text-primary: #111827;
  --text-secondary: #6B7280;
  --border-color: #E5E7EB;
  --card-bg: #F8FAFC;
  --code-bg: #1E293B;
  --code-text: #F9FAFB;
}

/* Dark 模式 */
[data-theme="dark"] {
  --bg-primary: #0B132B;
  --bg-secondary: #1E293B;
  --text-primary: #F9FAFB;
  --text-secondary: #9CA3AF;
  --border-color: #334155;
  --card-bg: #1E293B;
  --code-bg: #0F172A;
  --code-text: #E2E8F0;
}
```

使用方式：`bg-[var(--bg-primary)]`、`text-[var(--text-secondary)]`

### 3.3 主题切换机制

**实现原理**：
1. 通过 `<html>` 标签的 `data-theme` 属性控制主题
2. 值为 `light` 或 `dark`
3. CSS 变量根据 `data-theme` 的值切换
4. 用户选择存储在 `localStorage` 中

**初始化流程**：
```
页面加载
  ↓
读取 localStorage.theme
  ↓
有值？→ 是 → 使用存储的值
  ↓
否 → 跟随系统偏好（prefers-color-scheme）
  ↓
设置 data-theme 属性
```

**避免闪烁（FOUC）**：
- 主题初始化脚本放在 `<head>` 中，内联执行
- 在页面渲染前就设置好 data-theme
- 确保不会出现「先亮后暗」的闪烁

## 四、国际化（i18n）设计

### 4.1 路由设计

| 语言 | 路径前缀 | 示例 |
|------|----------|------|
| 中文（默认） | 无前缀 | `/`、`/protocol`、`/architecture` |
| 英文 | `/en` | `/en`、`/en/protocol`、`/en/architecture` |

**为什么中文不加前缀**：
- 主要用户是中文用户
- URL 更简洁
- 符合国内网站惯例

### 4.2 Astro i18n 配置

```typescript
// astro.config.ts
i18n: {
  defaultLocale: 'zh-cn',
  locales: ['zh-cn', 'en'],
  routing: {
    prefixDefaultLocale: false, // 默认语言不加前缀
  },
}
```

### 4.3 工具函数

**核心函数**：

| 函数 | 作用 | 参数 | 返回值 |
|------|------|------|--------|
| `getLangFromPath(pathname)` | 从 URL 判断当前语言 | pathname: string | 'zh-cn' \| 'en' |
| `getTranslation(pathname)` | 获取当前语言的翻译对象 | pathname: string | Translation 对象 |
| `getAlternatePath(pathname, targetLang)` | 计算切换语言后的目标 URL | pathname, targetLang | string |

**使用示例**：
```astro
---
import { getTranslation } from '@/i18n/utils';

const t = getTranslation(Astro.url.pathname);
---

<h1>{t.hero.title}</h1>
<button>{t.common.getStarted}</button>
```

### 5.1 组件分层

```
Layout 层（页面框架）
    ↓
Section 层（页面区块）
    ↓
Common 层（通用组件）
```

**Layout 组件**：
- MainLayout — 全站主布局
- Header — 顶部导航
- Footer — 底部
- ThemeToggle — 主题切换
- LanguageSwitcher — 语言切换

**Section 组件**（首页）：
- Hero — 首屏
- EvidenceFlow — 证据流程
- CryptoOverview — 密码学能力
- PackagePreview — 证据包结构
- VerificationProcess — 验证流程
- DeveloperEntry — 开发者入口
- UseCases — 应用场景
- ComingSoon — 即将推出

**Common 组件**：
- Button — 按钮
- Card — 卡片容器
- SectionTitle — 区块标题
- CodeBlock — 代码块
- ToolCard — 工具卡片

### 5.2 组件规范

**Props 定义**：
- 所有组件 Props 必须定义 TypeScript 类型
- 禁止使用 `any`
- Props 驱动，不依赖外部全局状态

**命名规范**：
- 组件文件名：PascalCase（`HeroSection.astro`）
- Props 接口：`ComponentNameProps`
- 事件处理：`onXxx` 命名

**单一职责**：
- 一个组件只做一件事
- 复杂组件拆分为子组件
- 业务逻辑和展示分离

### 5.3 通用组件设计

#### Button 组件

**Props**：
```typescript
interface ButtonProps {
  variant?: 'primary' | 'secondary' | 'outline';
  size?: 'sm' | 'md' | 'lg';
  href?: string;        // 链接按钮
  type?: 'button' | 'submit';
  class?: string;       // 自定义样式
}
```

**Variant 样式**：
- primary：主色背景 + 白色文字
- secondary：次级背景 + 主色文字
- outline：透明背景 + 主色边框 + 主色文字

#### Card 组件

**Props**：
```typescript
interface CardProps {
  hover?: boolean;       // 是否有悬停效果
  class?: string;
}
```

**样式**：
- 圆角（rounded-lg）
- 边框（border）
- 背景（var(--card-bg)）
- 可选悬停：上浮 + 阴影增强

#### SectionTitle 组件

**Props**：
```typescript
interface SectionTitleProps {
  title: string;
  subtitle?: string;
  align?: 'left' | 'center';
}
```

#### CodeBlock 组件

**Props**：
```typescript
interface CodeBlockProps {
  code: string;
  language?: string;
}
```

**样式**：
- 深色背景（var(--code-bg)）
- 等宽字体（font-mono）
- 圆角 + padding
- 横向滚动（overflow-x-auto）

## 七、SVG 架构图设计

### 7.1 为什么必须用 SVG

| 对比项 | SVG | PNG/JPG |
|--------|-----|---------|
| 缩放 | 无损 | 模糊 |
| 文件大小 | 小（简单图形） | 大 |
| 主题适配 | 支持（CSS 变量） | 不支持 |
| 可维护性 | 可编辑代码 | 需要设计软件 |
| 技术可信度 | 高（技术网站标配） | 低 |

**结论**：技术网站的架构图、流程图必须用 SVG，这是专业度的体现。

### 7.2 五层架构图设计

**结构**：
```
┌─────────────────────────────────────┐
│   AI Application Layer              │  ← 应用层
├─────────────────────────────────────┤
│   Evidence Capture Layer            │  ← 采集层
├─────────────────────────────────────┤
│   Evidence Model Layer              │  ← 模型层
├─────────────────────────────────────┤
│   Cryptographic Layer               │  ← 密码学层
├─────────────────────────────────────┤
│   Verification Layer                │  ← 验证层
└─────────────────────────────────────┘
```

**SVG 实现要点**：
- 使用 `viewBox` 确保响应式
- 每层一个 `<rect>` + `<text>`
- 层之间用箭头（`<path>` 或 `<line>` + `<polygon>`）
- 颜色用 CSS 变量或 `currentColor`，适配明暗主题
- 文字用 `<text>`，字体继承系统字体

### 7.3 证据图谱示意图

**结构**：
- 节点：Artifact、Event、Identity
- 关系：generatedBy、used、precededBy
- 有向图，箭头表示关系方向

## 八、部署方案

### 8.1 Docker 多阶段构建

**构建流程**：
```
Stage 1: Builder (node:20-alpine)
  ├── 安装 pnpm
  ├── 安装依赖（--frozen-lockfile）
  ├── 复制源码
  └── pnpm build → dist/

Stage 2: Runtime (nginx:alpine)
  ├── 从 builder 复制 dist/
  ├── 复制 nginx 配置
  └── 启动 Nginx
```

**优势**：
- 最终镜像只包含 Nginx + 静态文件
- 镜像体积小（~50MB）
- 构建环境和运行环境隔离
- 安全（不包含 node_modules、源码等）

### 8.2 Nginx 配置

**核心配置项**：

| 配置 | 值 | 说明 |
|------|-----|------|
| 监听端口 | 80 | HTTP 端口 |
| 根目录 | /usr/share/nginx/html | 静态文件目录 |
| Gzip | on | 开启压缩 |
| Gzip 类型 | text/css, application/javascript, image/svg+xml, ... | 压缩的文件类型 |
| HTML 缓存 | no-cache | 每次验证 |
| 静态资源缓存 | 30d + immutable | JS/CSS/图片强缓存 |
| try_files | $uri $uri/ /index.html | 路由回退 |

**缓存策略说明**：
- HTML 文件：不缓存，因为内容可能更新
- JS/CSS/图片：强缓存 30 天，因为 Astro 构建时会加 hash 指纹，文件名变了就自动失效

### 8.3 docker-compose 配置

```yaml
    build:
      context: ..
```

## 九、开发规范

### 9.1 Git 规范

**Commit Message 格式**：
```
<type>(<scope>): <subject>
```

**Type 类型**：

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 bug |
| docs | 文档更新 |
| style | 样式调整（不影响功能） |
| refactor | 重构（不新增功能，不修 bug） |
| chore | 构建/工具/依赖调整 |
| test | 测试相关 |

**示例**：
```
feat(home): add hero section
fix(header): mobile menu overflow
chore(deps): upgrade astro to 4.5.0
docs(readme): add deployment instructions
```

### 9.2 代码规范

**TypeScript**：
- strict 模式
- 禁止 `any` 类型
- 禁止非空断言 `!`（除非绝对必要并加注释）
- 所有函数参数和返回值必须有类型

**组件**：
- 单一职责
- Props 驱动
- 文件名 PascalCase
- 一个文件一个组件

**样式**：
- 优先 Tailwind utility class
- 复杂样式用 scoped style
- 颜色用 CSS 变量或主题色，禁止硬编码
- 响应式：移动端优先，md: lg: 增强

**内容**：
- 所有用户可见文本走 i18n
- 禁止在组件中硬编码大段文本
- 代码内容不翻译

### 9.3 安全规范

- 禁止硬编码密钥、密码、Token
- 禁止引入已知有安全漏洞的依赖
- 第三方链接加 `rel="noopener noreferrer"`
- 用户输入必须转义和验证（v0.1 暂无用户输入）
