## 一、项目概述

### 1.1 项目背景

AEP（AI Evidence Protocol）是一个为 AI 生成内容提供可信数字证明的开放协议。通过密码学、时间证明和可验证数据结构，建立 AI 内容从生成到验证的完整可信链路。

本项目是 AEP 协议的官方网站，作为协议的展示窗口、开发者入口和生态建设起点。

### 1.2 项目定位

AEP 官网不是一个普通的产品官网，而是：

```
Protocol + Toolchain + Ecosystem
   ↑        ↑          ↑
协议展示   工具入口    生态起点
```

**核心理念**：协议项目不是做网站，而是做 Protocol + Toolchain + Ecosystem。网站只是入口。

### 1.3 目标用户

| 用户类型 | 核心需求 | 关注内容 |
|----------|----------|----------|
| 技术决策者 | 了解协议价值、评估可行性 | 首页、协议页、安全页 |
| 开发者 | 快速上手、获取工具 | 开发者页、下载页、文档 |
| 企业用户 | 评估企业级应用方案 | 架构页、安全页、应用场景 |
| 研究者 | 深入了解技术细节 | 协议页、架构页、安全页 |

### 1.4 项目目标（v0.1）

1. **建立品牌认知** — 让访客快速理解 AEP 是什么、解决什么问题
2. **展示技术实力** — 通过专业的技术内容和架构图建立可信度
3. **开发者入口** — 提供 MCP、CLI 等工具的介绍和下载入口
4. **国际化基础** — 中英文双语，为全球生态做准备
5. **可部署上线** — Docker 一键部署，可直接用于生产环境

- AEP 提供什么样的安全保证
- 安全设计的核心理念

##### 3. 密码学基础（4 个卡片）
1. **SM2 数字签名算法** — 国密标准，非对称加密，来源认证和不可否认

3. **Merkle 树证明** — 高效集合完整性验证，支持海量数据
4. **时间戳机制** — 时间证明，防止重放攻击

##### 4. 威胁模型
- 内容篡改检测 → 哈希 + 签名
- 身份伪造防护 → 数字签名 + 身份验证
- 重放攻击防护 → 时间戳 + 序列号
- （每个威胁 + 对应防护机制）

##### 5. 验证流程详解
- 七阶段验证的简要说明
- 每个阶段验证什么

##### 6. 安全声明
- 客观、严谨的表述
- 说明 AEP 的能力边界
- 说明基于的密码学假设

> **红线**：禁止出现「绝对安全」「不可破解」「100% 可信」「完全保证」等夸大表述。
